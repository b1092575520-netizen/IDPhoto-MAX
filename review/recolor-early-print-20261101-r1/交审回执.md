## 实现与核对点

- `resolveDependencies` 不因 request 已暴露而丢失 v2 早打绑定；核对上下文、原片、消费者/来源和附件后，批量查询真实补传任务及原目标。仅 unknown/unblocked 或 TASK_PENDING/无 DeliveryId 的接收窗口回查原目标，再核对有效状态及 code/contextKey/deliveryId。
- 同规格 `pendingClick` 只打印，复用原任务/清单/照片字节；不同规格沿同码先打。只要前序尚未远端发布，就不生成后序追加 request；本地 complete 不能代替远端 ready，上传中的 owned pendingBatch 只静默等待。最终 request 使用发布后的 groupVersion。
- 后续打印任务在本地 context 记 `foregroundOnly`。前台失败时，无 request 则停下供店员再点；已有 request 则保留并待核对。自动恢复重复检查，完整先打才可只交文件，其余不进入旧 retryPending 的 PS 重排/存档路径。
- 码/连接不符、未知、离线、取消/撤回和冲突仍拒绝；不改交接协议字段、云端、桌面或像素模块。受管存档延期到下次前台打印维持终审已接受的例外。
