# 取件码模式修复

目标日期：2026-09-28；基线 v0.6.1，当前开发版本 v0.6.2。“自动取码接入与来源兼容整改”尚未冻结候选或完成实际运行副本升级。保留取码失败中止输出规则；本轮增加本机连接核对、历史补交确认与稳定原任务重试，云端、小程序和多规格草稿发布门禁不变。

## 操作

- 输出选项中的“取件码模式”默认关闭，重开插件记住上次明确选择。写入设置失败会说明未改变，不假称已保存。
- 关闭：使用“开始排版”、双击模板或快捷键，保留当前 11 模板、照片尺寸、普通信息条和 JPG/NAS/打印选项，不创建交付或取码请求，不显示取件码字段，也不显示任何“待补码”替代文字。
- 开启：上述普通入口先判断本次照片来源；只有原规则认定的本店当天新拍照片自动进入单规格交付。先核对本机交接，再保留独立高清成片并请求本次后台确认；只有有效六位码才继续拼版和原输出选项。
- 外来、历史重印、日期/来源不明照片继续原普通排版，整条信息条留白，没有店铺文字、日期、二维码或取件码；不准备交付专用副本、不请求后台、不限制普通多模板，不要求反复切模式。照片数量、布局、普通 JPG/NAS 资格与打印选项不变。明确撤销“所有照片都取码上传”的错误方案。
- 本店旧片需补交时选择显式交付入口，单独确认本次照片是本店旧片且尚未交付；已有交付可选择原任务重导信息条，需要修改照片则在后台原交付补交／修订。确认不延续到下一位顾客，不更改相机登记或普通归档资格；拍摄日期缺失时留空，不用当前日期代替。
- 显式“排版并交付”“仅电子交付”仍强制取码，与普通入口开关无关。纯电子不启动打印桥。多规格草稿继续先生成、后台人工核对后完成，不因这个开关擅自自动发布。
- 无后台、断网、无效/旧/跨任务/终态回执，或交接准备失败时显示 Photoshop 原生弹窗并中止；所选尺寸保留，任务结束后可主动切换模式。视觉检查显式禁用交付、JPG/NAS 和打印。

## 中止和恢复

主界面“交付连接与恢复”统一提供连接检测和未完成任务处理，详细路径放在展开诊断中。连接检测仅以本次随机请求核对同一目录、消费者和兼容协议，不预占取件码；本机连通不等于云端可用。本机握手上限 6 秒，断开时如实说明尚未确认后台启动或目录匹配，不能一律归为网络错误。取码交付在创建任务前做同样核对；普通分支不调用检测。

每次取码最多等 60 秒，每 200ms 检查一次，显示等待和停止入口，不占 Photoshop 模态锁等网络。本轮专用测试队列的真实 worker／测试云确认实测约 3.003 秒；60 秒预算覆盖后台 10 秒补扫及一次 45 秒 HTTP 请求并留出调度余量，不保证拥堵时每次成功，不自动延长或新建任务。有效码至少含一个字母和数字，字符集、requestId、原任务/清单/交付/连接绑定沿用现有协议；插件不自行随机生成或借用归档文件名中的短码。只有绑定本次请求的否定回执才能说明认证、云连接、超时或本地核对错误，旧／跨任务错误也不能冒充当前诊断。

失败发生在创建六寸拼版或独立信息条之前。普通 JPG/NAS 和打印不会执行；为请求取件码保存的 `photo.jpg`、请求及上下文可能已经存在，保留供后台核对，不能将此说成“磁盘没有写入”。临时处理文档按所属任务关闭，不关闭原片。不写 `complete.json`，迟到取码和网络恢复不会自动完成、发布或打印。

错误状态写入或临时副本关闭再次失败时，将原因附加到取码主错误，仍弹窗中止，不能被二次错误覆盖。尽力清理每个所属副本，清理失败会说明；已经完成交付后的清理失败保持普通错误，不冒称没有取得码或没有成品。

未完成任务的目录引用持久保留，重开插件或重复点击不能自动新建交付。在“交付连接与恢复”核对原照片名称与输出选项后，明确点击“继续原任务”，复用原任务、清单、独立成片、模板／设置快照及原消费者和云端连接，以新的请求号重新核对码；校验通过后才按原选项继续。请求写入失败但可靠准备记录仍在时，可校验原成片后补写同一请求，不重新裁图或建单。已经有输出开始、成品或信息条痕迹的任务不自动重跑，需人工核对，避免重复打印。纯电子恢复不打印。

“停止等待”仅停止本机等待，不取消云端任务；迟到回执不自动继续。若当前已换成另一位顾客，须明确选择保留旧任务并开始新顾客，不能按文件名猜测合并或共领。旧任务保持未完成。原任务补图仍只追加信息条，不替被中止任务补写原 `complete.json`。完成信号可靠保存后，即使状态／指针清理失败，也说明已完成的事实，不报成“本次未输出”。

已经取得有效码后，上传、NAS 与打印的状态继续分别报告；上传慢或之后打印失败不会自动重复打印。已成功生成过的历史文件不会被本修复自动改写或重印。

## 代码与验证入口

- `src/core/pickupCodeModeStore.js`：独立本地开关。
- `src/main.js`：普通/显式入口路由、模式锁和 Photoshop `app.showAlert`。
- `src/core/layoutWorkflow.js`：取码前后门禁及临时副本清理。
- `src/photoshop/deliveryService.js`：本次回执确认、无确认不完成、纯电子门禁。
- `src/photoshop/infoBarRenderer.js`：关闭模式省略码，开启模式缺码或缺位置拒绝渲染。

执行 `npm run verify`，包含插件全量测试、源码语法、版本、执行入口和发布文件检查。回归覆盖开关/重新加载、主按钮/双击/快捷键/显式入口、弹窗与互斥、11 模板有码/无码、空码/非法/迟到回执、单张与纯电子不输出以及多规格草稿兼容。该自动化验证使用 Photoshop/回执替身，不能代替真实宿主弹窗、真实后台/云端、物理出纸或用户体验。

本轮候选与独立还原结果使用主项目 `review/pickup-handoff-compat-fix/`，尚待冻结、还原及独立审查；已有 `review/pickup-code-mode-fix/` 是上一轮证据，不代表此次通过。既有阶段 7 发布包仍固定配套 0.6.0；本轮源码改动不会自动升级其运行副本或改变历史发布包。
