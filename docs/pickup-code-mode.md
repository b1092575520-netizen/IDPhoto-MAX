# 取件码模式修复

日期：2026-09-28；插件 v0.6.1。按用户最新要求，替代阶段 5 的“取码超时继续打印并显示待补码”规则。后台、云端、小程序协议和多规格草稿没有变更。

## 操作

- 输出选项中的“取件码模式”默认关闭，重开插件记住上次明确选择。写入设置失败会说明未改变，不假称已保存。
- 关闭：使用“开始排版”、双击模板或快捷键，保留当前 11 模板、照片尺寸、普通信息条和 JPG/NAS/打印选项，不创建交付或取码请求，不显示取件码字段，也不显示任何“待补码”替代文字。
- 开启：上述普通入口自动进入单规格交付。先保留独立高清成片并请求本次后台确认；只有有效六位码才继续拼版和原输出选项。一次多选会在创建任务前说明应使用多规格草稿或关闭模式。
- 显式“排版并交付”“仅电子交付”仍强制取码，与普通入口开关无关。纯电子不启动打印桥。多规格草稿继续先生成、后台人工核对后完成，不因这个开关擅自自动发布。
- 无后台、断网、无效/旧/跨任务/终态回执，或交接准备失败时显示 Photoshop 原生弹窗并中止；所选尺寸保留，任务结束后可主动切换模式。视觉检查显式禁用交付、JPG/NAS 和打印。

## 中止和恢复

取码仍最多等 4 秒，每 200ms 检查一次，不占 Photoshop 模态锁等网络。有效码至少含一个字母和数字，字符集、requestId、原任务/清单/交付/连接绑定沿用现有协议；插件不自行随机生成或借用归档文件名中的短码。

失败发生在创建六寸拼版或独立信息条之前。普通 JPG/NAS 和打印不会执行；为请求取件码保存的 `photo.jpg`、请求及上下文可能已经存在，保留供后台核对，不能将此说成“磁盘没有写入”。临时处理文档按所属任务关闭，不关闭原片。不写 `complete.json`，迟到取码和网络恢复不会自动完成、发布或打印。

错误状态写入或临时副本关闭再次失败时，将原因附加到取码主错误，仍弹窗中止，不能被二次错误覆盖。尽力清理每个所属副本，清理失败会说明；已经完成交付后的清理失败保持普通错误，不冒称没有取得码或没有成品。

如后台已有这次中止任务，应核对后取消未完成任务，或按原后台人工恢复流程处理；不要把“补原任务信息条”当成被中止任务已经完成。补图只追加信息条，不补写原 `complete.json`。确认要重新执行时才发起新的排版动作，不能因超时自动新建任务。

已经取得有效码后，上传、NAS 与打印的状态继续分别报告；上传慢或之后打印失败不会自动重复打印。已成功生成过的历史文件不会被本修复自动改写或重印。

## 代码与验证入口

- `src/core/pickupCodeModeStore.js`：独立本地开关。
- `src/main.js`：普通/显式入口路由、模式锁和 Photoshop `app.showAlert`。
- `src/core/layoutWorkflow.js`：取码前后门禁及临时副本清理。
- `src/photoshop/deliveryService.js`：本次回执确认、无确认不完成、纯电子门禁。
- `src/photoshop/infoBarRenderer.js`：关闭模式省略码，开启模式缺码或缺位置拒绝渲染。

执行 `npm run verify`，包含插件全量测试、源码语法、版本、执行入口和发布文件检查。回归覆盖开关/重新加载、主按钮/双击/快捷键/显式入口、弹窗与互斥、11 模板有码/无码、空码/非法/迟到回执、单张与纯电子不输出以及多规格草稿兼容。该自动化验证使用 Photoshop/回执替身，不能代替真实宿主弹窗、真实后台/云端、物理出纸或用户体验。

本轮固定候选与独立还原结果存放在主项目 `review/pickup-code-mode-fix/`，独立审查应使用新目录、绑定 SNAPSHOT 摘要。既有阶段 7 发布包仍固定配套 0.6.0；本轮源码/插件候选不会自动升级其运行副本或改变历史发布包。
