# v0.6.8 插件交付自动化与新原片身份

2026-10-15增量：没有ImageUniqueID或OriginalDocumentID的新原片，可用机身序列号＋完整DateTimeOriginal＋原始亚秒建立 `source-v2` 身份，时区偏移可读时保留。身份强度另行区分（相机编号/原片文档编号/拍摄亚秒），强编号格式或同文档字段冲突仍拒绝。无亚秒且无强编号仍无身份。原有有强编号、无亚秒的合法 `source-v1` 继续兼容。

EXIF `53`表示原始亚秒数字；Photoshop可能写成内嵌`.053`。有单独EXIF亚秒时，以原数字串为准，只接受标准小数尾零等价或已核实的1/2位亚秒左补到3位映射，其余冲突返回空身份。零亚秒是有效值，不等同于缺失。单独偏移从OffsetTimeOriginal读取；不使用保存/修改/数字化时间。

同一原片首次保存补出OriginalDocumentID不会改变source-v2键，文件名、像素和普通DocumentID仍无关。原索引中精确匹配同机身/完整原拍摄时间/亚秒的source-v1任务会继续沿用旧键和原任务，不改写原记录；已有强编号与当前同类型编号冲突时不匹配，多个旧键同时匹配则停止交付人工核对。接受同机身极端同刻亚秒碰撞为同原片的风险，是本轮用户明确决定，不扩大为顾客权限。

取件码模式无法读身份时，最终状态栏显示“这张照片读不到拍摄编号，本次只排版、不出取件码”；外来、旧片、日期不明保留来源检查原message。没有新增按钮或弹窗。0.6.8覆盖日常前需完成本轮实测/发布校验、本地Git提交及上一版回退，覆盖前告知用户；实际安装状态以本轮回执为准。

## 0.6.30 同顾客先打与纯文件补传

后台的本次 `queryTasks` 确认原单 alive/preparing，且码、原连接和归属有效时，同原片的单独点击与多尺寸都可先打。码来自本次查询，专属链接从原任务回执绑定同任务、manifest、requestId、context/delivery 和 entryLinkCode；格式校验与渲染器 jsQR 回读沿用。拿不到合法链接才按原规则留有原因地用统一入口，绝不携带其他码的专属链接。未知、离线、冲突均不凭本地码出片。

`early-print.json` 是插件本地恢复记录，v2 绑定 contextFingerprint、原任务目标和码、专属链接、当次 layout/info 摘要及输出提交状态。photo、layout、info 都在点击时保存；阻止或 Esc 停单。未确认的打印结果或附件缺损停止自动恢复，原文件保留，不重新打印。旧 v1 缺少完整附件和打印确认，保留并提示人工核对。

恢复只校验文件、提交原协议 request/complete 并确认纸上码，不调用 Photoshop、存档或打印桥。其余可能产生权限框的恢复保持十分钟暂停；纯文件先打恢复绕过该暂停。重启后继续同任务，取消/撤回或换码则停下并提示纸上码失效，不能悄悄建新码交付。

同规格挂起任务已先打：新点击只打印，不新建交付，不改旧成片；新点击取消不撤销前一次成功先打。尚未先打：查询证实未接收，且从未发布 request 时，旧单记 stopped“店员已重新排”后重走；一旦 request 暴露，即使查询暂时 unknown 也不能重建，先取得可信后台状态再复用，避免读取/接收竞态。被拒收或归属不明的任务继续保护。

受管 NAS 存档要求正式 request/manifest；尚未形成该清单的先打单把 photo 保留在任务目录，受管存档留到下一次前台打印处理。补传后台不单独请求授权。以上不改变交接协议字段、云端或桌面后台。

### REP-01 / R1 接收窗口与串行补传

已有 v2 先打记录的补传单，request 已暴露但仍 unknown，或已登记但返回 `TASK_PENDING` 且无 DeliveryId 时，本次查询回查记录中的 targetTaskId。只有原连接一致、原目标 known 且未 blocked、码有效、状态 ready/preparing，并且 code/contextKey/deliveryId 与记录一致，才准许前台输出。同规格复用原补传单及原成片；不同规格也先打，等待前面规格远端发布后才生成追加清单，使用新查回的 groupVersion。本地写完 complete 不代表远端发布。已拥有的 pendingBatch 上传阶段仅后台等待，不授权新输出或并发追加。

后续规格的本地 context 保存 `foregroundOnly`。前台失败而未形成完整先打输出时，没有暴露 request 的任务停下，店员恢复连接后可再点；已有 request 的保留任务和原字节并待人工核对，不重复建单。自动恢复同样检查此标记；只有提交确认且附件完整的先打任务可以纯文件补传，不落入旧 PS 重排/存档恢复。

### REP-02 / R2 已终结的先打历史

先通过本次 `queryTasks` 查询每份历史先打任务自身的远端状态，再决定是否读取其早打依赖。已知且无错误的 ready（未 blocked、无 pendingBatch）、withdrawn 或 cancelled，按普通旧规格进入原有 `requireItem` 逻辑：有效则沿当前码追加/替换；撤回或取消则作为结束的旧交付，新点击取新码，不复活旧码。远端撤回本身返回 blocked 不阻断原有终态分支。

未登记、TASK_PENDING/无 DeliveryId、TASK_PENDING/pendingBatch 上传中以及 preparing 仍保留早打绑定、原连接校验和串行补传保护。本地 completed 不能让在途记录绕过远端校验。在途记录回查发现原目标已撤回或取消时，继续拒绝并提示纸上码失效、请重排。错误、冲突、未知与离线不作为已终结的授权结果。
