- **执行**：**Codex**。用户 11-01 因 Claude 额度紧改派；插件业务逻辑本来就归 Codex。面板文字按本文件写死，不自加按钮或入口。
- **推理强度**：**超高**。改的是取件码和交付逻辑。
- **顺序**：先做这份（0.6.30），再做同日的[提速：带码单出片](提速-带码单出片-2026-11-01.md)（顺延 0.6.31，仍归 Claude 插件会话）。两份都会碰 `layoutWorkflow.js`，提速要等这份装好后再开工。

## 1. 出了什么事（11-01 实单）

同一张原片（1M9A6087）先排红底 1 寸，带码打印（M8SYKB，专属码）。没有退历史记录，直接把图层改成白底，再点打印。结果弹出“这个尺寸稍后自动补上”，之后怎么点都卡住，只能关掉取件码模式才打出来。约 4 分钟后，PS 突然弹出权限框。

证据在 `%APPDATA%\Adobe\Adobe Photoshop 2026\Logs\UXPLogs_2026-11-01_12-39-32_477296.log`（插件线程 32496），插件数据在 `PluginData\delivery-handoffs-v1\2026\2026-11\2026-11-01\`，交付队列在 `%LOCALAPPDATA%\YxPhotoImporter\queue-v1\`。

| 时间 | 发生了什么 |
|---|---|
| 16:01:17 | 另一张照片的打印权限框点了“阻止”（这次打印没有 `[print] timing` 行；16:01:31 重排后打出）。`printService.lastDeniedAt` 记下这个时间。 |
| 16:06:42–51 | 红底带码打印，任务 fda6a596，M8SYKB 专属码。 |
| 16:07:00–03 | 点白底。`automation-requests/9536d4cd…` 查到红底那单 `status` 还是 preparing，`deliveryAutomationService.js:165` 抛出 AUTO_TARGET_PREPARING。没有多尺寸的 `sharedDelivery`，所以 `layoutWorkflow.js:513` 没走先打，直接报错弹框。白底任务 c4cc9ea9 被记成 retryable。 |
| 16:07:04 | 红底那单在队列里变成 ready，只比点击晚 1 秒。 |
| 16:07:38–16:08:39 | 店员又点了 5 次，每次都被 `deliveryService.js:226-229` 以 AUTO_TASK_PENDING 拦下。 |
| 16:08:46–54 | 关掉取件码模式后打出来了（不交付）。16:09:05 店员在交付管理手动补交了一张白底（队列 36c4da45，“店员编辑照片”）。 |

| 16:11:22–37 | 后台自己补做白底：在 PS 里重新建画布排版（16:11:29），信息条印的是 **通用码**（日志写“[entry-code] M8SYKB 通用码：没有专属链接”）；存档要启动打印桥，弹出权限框，店员点了“阻止”，结果“这次没存档”。白底补进了同一交付，于是顾客那里有两张白底。 |

**结论**：底色不是问题。`specKey` 带底色，红、白本来就该是同一顾客名下的两个版本。真正的问题有四个：

1. 换底色时上一单还没到“可领取”，就不让出纸，只能挂起；
2. 挂起的单子会挡住店员后面的每一次点击；
3. 挂起单的补做被“阻止后暂停 10 分钟”拖住了；
4. 迟到的补做要在 PS 里重排、印通用码、单独弹权限框。

## 2. 改成什么样（店员看到的）

同一顾客的另一个规格（换底色、换尺寸，或同规格重排）：

1. **点了就出**：立刻排版，信息条印这位顾客现有的取件码和**同一张专属码**，照常弹一次打印框。不弹“稍后自动补上”的模态框，只在面板状态栏写一句，例如“取件码 M8SYKB · 这张电子版稍后自动补上”。
2. **照片后台自己传**：上一单到“可领取”后，后台自动把这张加进同一交付。整个过程**不弹任何框，也不在 PS 里开文档**。
3. **打印框点“阻止”就是这单不要了**：不出纸，后台也不传，交付里不会多出这张。
4. **连点多个规格不用等**。同一规格再点一次（重排）也是立刻出、同一个码，交付里这个规格只留一张。
5. **之前点过“阻止”也不影响**：补传不弹框，所以不受 10 分钟暂停限制。
6. **很少见的情况**：上一单最后没成（被取消、撤回，或后台给了别的码），面板沿用现有提示“纸上印的取件码 X 已不能用，现在是 Y，请重排这个尺寸”，不偷偷换码。

## 3. 实现要求

- **先打的触发条件不变**：后台查回原交付是 AUTO_TARGET_PREPARING，也就是活着、正在准备。码以这次查询结果为准，不信本地旧记录。原交付已取消或已撤回时，仍按现有规则当新顾客处理。查不到、交付管理没开时，仍按现有提示走，不凭本地记录先打。
- **专属码**：先打用的专属链接必须是这个码的那一张（三重核对和 jsQR 回读照旧）。先打和后台补传都不许退回通用码。确实拿不到时，按现有规则退回通用码，并在日志写明原因。
- **把多尺寸的先打推广到单独点击**：`layoutWorkflow.js:511-521` 现在只认 `sharedDelivery`。改成单独点击、只要拿到了查询结果里的码和专属链接，也走 `markEarlyPrint`。
- **AUTO_TASK_PENDING 不再挡店员**：同一原片同一规格已有挂起任务时：
  - 挂起的那单已经先打过（有 `early-print.json`）：这次只打印，沿用同一个码，不新建任务，不重复交付。
  - 挂起的那单还没出过纸：先核对它在后台的状态。后台还没接收的，就停掉它（记“店员已重新排”），按这次点击重新走；后台已经接收的，就让它继续传，这次只打印。
  - 任何情况都**不能重复交付或丢照片**。
- **存档和排版图在点击时就存好**：先打的那次，存档随打印一起走，只弹一个框。这次打出来的排版图和信息条图也当场存进任务目录。后台补传只交文件，不在 PS 里重排，不启动打印桥。万一存档必须等交付确认，后台补传时也不存，留到下一次店员前台打印时顺带存掉，**后台不许单独弹框**。
- **10 分钟暂停只管会弹框的后台工作**。先打过的单子补传不受它限制，其余单子维持现状。
- **“阻止”的处理**：先打那次的打印框点了“阻止”或按 Esc，就把这单标成“店员取消了这单”（stopped），后台不再补传。
- **重启**：插件或 PS 重启后，挂着的补传继续，不重复，不丢。
- 不改桌面交付管理和云函数，不改交接协议字段。真要改，写进本文件交给 Claude 裁定。
