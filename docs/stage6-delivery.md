## 使用

1. 打开处理完成且来源合格的照片，选择多规格草稿。填写有效 JPG 文件名、用途/底色及实际要求；宽高均空时保持原尺寸。未确认的报名标准留空。
2. 可添加不同尺寸、大小与命名的版本。每份实际 duplicate/resize/JPG 编码，核像素与字节；不满足时报失败，保留独立原尺寸副本，不静默放大/裁切。
3. 同行共领：后台先选择已发布交付并导出目标 JSON，在插件明确选择并核对缩略图和主码。本次目标绑定当前活动照片、目标 ID、原连接和版本。完成、关闭或切换照片后不得沿用；下一人需重新选择。
4. 生成只写持久草稿。后台核对缩略图、数量和文件用途后点击“完成交付”，才完整发布。普通保存/文件事件/重启不等于确认。
5. 发布后“补原任务信息条”。拆分后的新交付在后台导出信息条任务，在插件“选择原任务补码”选择返回目录；当次向原后台确认有效码，渲染后再次确认。此路径不上传交付原片、不重印。

## 协议与恢复

旧 request v1 单 photo 不变；多规格 request v2 支持 1–20 个 photo，交给 manifest v3 消费者。informationOnly 引用包含 referenceDeliveryId、referenceContextKey、referenceFileId、referenceRevision；任一原文件版本失配均拒绝补码。新消费者读取旧任务；旧消费者不能处理 v3。先停止旧后台并保留队列备份，再更新配套程序，不能用旧版本打开新队列。

主云单张 8MiB/20MP，目标组 8 成员/20 当前文件/16 领取来源范围。原片归档去重与顾客交付版本互不删除。没有真实统一入口小程序码时省略，不生成假码。原有模板尺寸/照片数量本阶段未修改。

## 验证边界

自动化测试含真实编码规格检查的服务替身、完成门禁、目标清除及当次补码确认；`npm run verify` 另检查完整源码语法、版本和 Photoshop 执行入口。真实 Photoshop 测试使用已授权测试副本，并对该副本注入来源资格 metadata fixture；不冒充相机来源验收。

三份真实 JPG 在模拟器读取后 SHA256 与 Photoshop 导出相同，发布前有后台草稿窗口与明确完成操作。当前有效码信息条已由真实 Photoshop 导出。第二真实身份、真手机保存/发送、实体打印/装袋与门店高峰体验尚未验收。桌面操作被用户 Esc 停止后的未完成项目须在主项目交接中继续列明。
