# v0.5.2 可靠性审查

## 检查方法与范围

从六条业务要求检查实际调用路径：原片保持不变；复制与关闭必须指向明确文档；宿主失败/取消不能被当成成功；照片身份不足时不能误合并；写入中断不能覆盖有效记录；打印结果必须区分未提交、已提交和无法确认。

检查范围包括原片/XMP读取、比例与裁切、扩图、画布、图层、信息条、多模板事务、JPG/NAS、身份判断、打印服务与 Windows 桥、设置读写与恢复、UI结果和发布产物。保留此前的工作区改动，未提交 Git、未清理顾客照片、未发送打印任务。

## 已确认与修复的缺陷

| 问题组 | 修复及影响 |
| --- | --- |
| Photoshop 错误被忽略 | `batchPlay` 可成功返回包含 `_obj: error` 的结果数组。共享执行层现在检查结果并抛出原错误代码，避免失败后继续拼版或冲印。 |
| 取消后继续执行 | DOM备用路径、扩图、字体/图层操作和模板循环现在保留取消状态，关闭临时单张并停止后续模板。 |
| 目标文档不明确 | 文档没有 `activate()` 时原逻辑直接跳过激活。改用官方 `app.activeDocument`，关闭使用原生 `closeWithoutSaving`、官方枚举或明确文档 ID；复制结果若与原片同 ID 则停止，不能压平或关闭原片。 |
| 打印失败与未知状态混淆 | 超时、损坏/不匹配回执、提交后异常都显示结果无法确认，提醒先看队列和出纸；不自动重试、不自动关闭未知结果的拼版。成功提示表示提交到打印队列，不能证明已出纸。 |
| 打印重复执行与回执时序 | 使用独占创建的 `.submitted` 标记阻止同一作业二次提交；回执先写临时文件再替换，暂未写完整时继续等待；解析作业后再验证打印机，检查失败也能返回关联回执。 |
| 临时图残留 | 提交前失败清理未提交 JPG/作业文件；打印桥先释放图片与打印对象再发布成功，避免 UXP 清理时遇到仍被占用的 JPG。未知结果保留证据；微小的提交标记保留作防重复依据。 |
| 存档证据与像素样本不足 | 索引改为写完临时文件后替换，不直接截断原索引；目录读取失败停止写入。不完整的 RGB 数据报错，中央区域无结构的样本不再生成可信视觉身份。 |
| 设置与UI误报 | 本地存储缺失、档案损坏或版本不兼容均报错，保留原数据；导入拒绝无版本的不明 JSON。调试参数保存/重置失败不再显示成功或应用未保存值；相机登记状态与当前照片存档资格分开显示。 |

宿主行为依据：Adobe [batchPlay](https://developer.adobe.com/photoshop/uxp/ps_reference/media/batchplay/)、[app.activeDocument](https://developer.adobe.com/photoshop/uxp/ps_reference/classes/photoshop/)、[Document关闭接口](https://developer.adobe.com/photoshop/uxp/ps_reference/classes/document/)、[UXP文件移动接口](https://developer.adobe.com/photoshop/uxp/2022/uxp-api/reference-js/modules/uxp/persistent-file-storage/storage)。

## 未完成的实机验证与适用边界

当前会话未暴露 `node_repl` 桌面控制工具。已检查 computer-use 的技能及运行说明，其要求使用 `node_repl` 操作 Windows；本轮未执行 Photoshop 宿主UI验证。未把 Node模拟、Windows文件系统探针或构建成功当成真实PS/NAS/纸张验收。

仍需在真实 Photoshop 上检查无 activate 方法时的实际文档切换、取消时标签与图层清理、真实照片底色/身份、NAS中断、打印队列和实体出纸。视觉签名是启发式比较，不是人脸身份认证，也不能证明任意照片集合绝无误判；缺少证据时保留或跳过，不凭短编号删除。多个电脑同时写同一日期索引的并发没有在本轮验证，当前串行队列仅覆盖单个插件实例。

建议验收：用当天本店新照做白/红/蓝底的一寸与二寸，确认三张最大尺寸 JPG；重新启动后重复不新增；旧照只排版。多模板执行中取消，确认后续模板未运行且原片仍在；打印超时时先核查队列，不直接再次点击打印。

本轮解决的是已确认缺陷和可验证的错误路径，不宣称插件已不存在任何未知 bug。
