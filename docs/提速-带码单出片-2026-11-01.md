# 提速：带码单出片（2026-11-01，Claude 定）

- **执行**：排版插件优化修复会话（Claude）。
- **推理强度**：**高**。只改出片速度，不碰取件码、存档归属和交付逻辑。
- **背景**：用户 11-01 同意“开始提速”。回码已由候选 40/42 降到约 1 秒，现在每单的等待主要在 Photoshop 里。

## 1. 实测（UXP 日志，10-29～11-01，26 单带码单）

日志位置：`%APPDATA%\Adobe\Adobe Photoshop 2026\Logs\UXPLogs_*.log`。下表按 `[execute] start` 到 `[execute] done` 的 `+毫秒` 拆分。

| 段 | 日志区间 | 常见耗时 | 说明 |
|---|---|---|---|
| 准备 | start → `[layout] placing photo copies` | 0.6–1.2 秒（偶尔 7–9 秒） | 读文档、裁图、建 3600×2400 画布。偶发的长等待要查是不是在等回码。 |
| **铺 8 张照片** | placing → `[infobar] rendering` | **1.3–3.9 秒，中位约 1.9 秒** | **最大、最不稳定的一段**。 |
| 信息条 | rendering → `[infobar] done` | 0.9–1.8 秒，中位约 1.05 秒 | 10-18 时是 3.6–4.5 秒，已经好很多。 |
| 保存 | → `layout and info saved` | 约 0.35 秒 | |
| 打印 | `[print] timing` | jpeg 约 0.25 秒；launch 0.7–3.8 秒（**含权限框等店员点**）；bridge 约 0.9 秒 | 权限框要保留（用户的“后悔药”），launch 不算进机器时间。 |

**整体**：一单中位约 8 秒，扣掉权限框约 7 秒。普通单（不带码）约 3 秒。

**其他线索**：
- 铺片和画信息条期间，日志里满是 Photoshop 自带模块的 `[DP] PSEvent sensor graph queue is full` 和 `Recommendation engine aborted`，说明每个图层操作都触发了 PS 自己的事件处理。可以测一下关掉“上下文任务栏”等推荐功能能快多少；这是 PS 设置，要不要改由用户定。
- 同一个码重印（11-01 11:22 那单 58G4PC），铺片用了 3.9 秒，比第一次的 1.55 秒慢一倍多，原因要查。

## 2. 目标

- 带码单机器时间（总耗时减 launch）中位 **≤ 4.5 秒**，现在约 7 秒。
- 铺 8 张 ≤ 0.8 秒且稳定；信息条 ≤ 0.8 秒。
- 普通单不能变慢。

## 3. 方向（先加细计时证实，再动手）

1. **铺片**：先给每张的复制、缩放、移动加细计时。可能的改法：
   - 先把裁好的照片缩到格子尺寸一次，再复制 7 份；
   - 或用 `imaging.getPixels` / `putPixels` 一次把像素盖到 8 个位置，少走图层和 batchPlay；
   - 或把 8 次操作合进一个 batchPlay。
2. **信息条**：给每个文字层的创建、旋转、栅格化计时，能合并的 batchPlay 合并。小程序码已经是 `putPixels`，不用动。
3. **准备段**：查偶发 7–9 秒的长等待是在等什么。
4. **PS 设置**：在用户同意后对比一次“上下文任务栏”开关前后的耗时，只记录数字，不擅自改用户设置。

## 4. 不能变的

- **出片像素一致**：11 个模板 ×（普通、带码）出片，和 0.6.29 逐像素比对。只允许文字抗锯齿这类肉眼看不出的差异，要给出差异像素数。
- 专属码的三重核对和 jsQR 回读照旧；卡片 60mm、文案、标准2寸 24px 下移都不变。
- 每次打印都弹权限框，不能绕过。
- 全部测试通过；按惯例提交、推送，PS 关掉后自动装，保留 0.6.29 回退。
- **装好后**：用户正常营业一天，再从 UXP 日志按第 1 节的表重算，对比提速前后。
